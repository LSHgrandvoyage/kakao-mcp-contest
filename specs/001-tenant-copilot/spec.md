# Spec: Lease Guide(전월세 길잡이) — 예선 MVP

> **무엇을·왜** 만드는지만 기술한다. 기술 선택(어떻게)은 `plan.md`.
> 상위 문서: `memory/constitution.md`(헌법, 우선) · `fable_context.md`(기획 인계 브리프).
> 범위: **Agentic Player 10 예선 MVP** — tool 3개로 엄격히 고정. 본선 확장 항목은 §4 Out of scope.

## 0. 서비스 식별 (description 필수 반영 — 헌법 §2)
- **서비스명(영문·국문 병기)**: `Lease Guide(전월세 길잡이)` — **확정**.
  - 모든 tool description에 이 병기 표기를 포함한다.
  - 포지셔닝 근거: "길잡이 = 여정을 안내하는 동반자" → 진단기가 아닌 생애주기 동반자 서사와 정합.
- **MCP Server Name**: `kakao` 미포함 확인 완료(헌법 §1).

## 1. 문제 & 목표
- **해결하려는 사용자 문제**: 전월세 임차인(비개발자)은 매물 검토 → 계약 → 입주 → 거주 → 퇴거/보증금
  회수의 각 시점에서 "지금 뭘 해야 하고 뭘 확인해야 하는지"를 모른다. 정보는 흩어져 있고,
  억 단위 재산이 걸린 판단을 혼자 내려야 한다.
- **가치 한 줄**: 임차 생애주기 전체에서 위험 신호를 짚어주고 다음 행동을 안내하는 **대화형 동반자**.
- **포지셔닝(차별화의 핵심)**: "계약 전 위험 진단기"가 아니라 **"임차 전 과정 동반자"**.
  기존 PlayMCP의 유사 서비스(단발성 진단 tool 1개)와 **문제 정의 차원에서** 구분된다.
  → "진단은 인생에 두어 번 쓰지만, 동반자는 임차 기간 내내 접점이 생긴다."
- **성공 기준(측정 가능)**:
  - 예선: tool 3개가 헌법의 HARD 제약(§1~§3-1)을 전부 통과하고 심사 승인.
  - 품질: 대표 시나리오(§2) 3건에서 LLM이 **올바른 tool을 선택**하고, 출력이 §3 제품 원칙
    (안전 판정 금지·면책·신뢰도 명시)을 위반하지 않음.
  - 성능: tool 호출 **평균 ≤100ms / p99 ≤3s**(헌법 §3).

## 2. 대상 사용자 & 사용 시나리오
- **주 사용자**: 전월세 계약을 앞두었거나 거주 중인 일반인(비개발자).
  판단 기준 — *"카카오톡에 있으면 우리 엄마도 쓸까?"*
- **대표 시나리오 (Given / When / Then)**:
  1. **매물 위험 점검** — Given 사용자가 계약을 고민 중인 매물이 있다.
     When "OO동 이 빌라 전세 2억인데 괜찮아?" 라고 묻는다.
     Then `diagnose_lease_risk`가 전세가율·시세 신뢰도·확인 항목·악성임대인 조회 결과를 반환하고,
     **"안전하다"는 판정 없이** 위험 신호와 다음 확인 행동을 안내한다.
  2. **시점별 할 일 안내** — Given 사용자가 잔금·입주일을 앞두고 있다.
     When "내일 잔금 치르는데 뭐 챙겨야 해?" 라고 묻는다.
     Then `get_stage_checklist`가 "잔금 → 즉시 전입신고 + 확정일자(대항력 발생 시점 결정)" 등
     해당 시점의 행동 순서와 확인 항목을 반환한다.
  3. **특약 문구 도움** — Given 사용자가 근저당 있는 신축 빌라 계약을 준비한다.
     When "근저당 있는 신축 빌라인데 특약에 뭘 넣어야 해?" 라고 묻는다.
     Then `generate_contract_clauses`가 상황에 맞는 특약 문구 후보 + 각 문구가 필요한 이유를 반환하고,
     **"법률 자문 아님, 공인중개사와 상의" 면책**을 포함한다.

## 3. Tools (기능 명세 — 구현 아님 · 헌법 §2 준수)

| Tool name | 목적(한 줄) | 입력(개념) | 출력(개념) | read-only | destructive |
|-----------|------------|-----------|-----------|-----------|-------------|
| `diagnose_lease_risk` | 매물의 임차 위험 신호 탐지 + 확인 항목 안내 | 주소, 보증금, 매물 유형 | 전세가율·위험 구간, 시세 신뢰도(근거 건수 포함), 등기부 직접확인 항목, 악성임대인 명단 조회 결과 | ✅ | ❌ |
| `get_stage_checklist` | 임차 생애주기 시점별 행동/확인 항목 안내 | 단계(매물탐색·계약전·계약일·잔금입주일·거주중·만기임박), 상황 옵션 | 해당 시점의 행동 순서 + 확인 항목 | ✅ | ❌ |
| `generate_contract_clauses` | 상황 맞춤 계약 특약 문구 후보 + 근거 제시 | 상황 서술(신축빌라·근저당·법인임대인 등) | 특약 문구 후보 목록 + 각 문구의 필요 이유 + 면책 문구 | ✅ | ❌ |

- 세 tool 모두 부작용 없음 → `readOnlyHint: true`, `destructiveHint: false`.
- 외부 데이터 의존 여부: `diagnose_lease_risk`는 공공데이터(→ 헌법 §3-1 사전적재 대상),
  나머지 둘은 **정적 콘텐츠 기반**(외부 의존 없음).
- annotations의 `openWorldHint`/`idempotentHint` 및 영문 description 최종값은 plan에서 확정.

## 4. 범위
- **In scope (예선 MVP)**: §3의 tool **3개**. 그 이상 없음.
- **`diagnose_lease_risk` 데이터 커버리지 (확정)**:
  - **지역**: 서울 **강남구** 단일 (법정동코드 `LAWD_CD = 11680`)
  - **건물 유형**: **아파트 + 연립다세대(빌라)** — 매매·전월세 각각 → 국토부 API **4종** 신청 대상
  - **기간**: 최근 **6개월** 실거래 사전적재
  - 커버리지 밖 주소 입력 시: 진단 대신 **"현재 강남구만 지원" 안내**를 반환(에러 아님).
- **Out of scope (본선 확장 후보 — spec에 스며들면 제거)**:
  - 보증금 반환 분쟁 대응(내용증명·임차권등기명령 안내)
  - Kakao Tools 위젯(위험도 게이지·타임라인 시각화)
  - 등기부등본·전세보증보험 데이터 소스 실시간 연동
  - `diagnose_lease_risk` 지원 지역/건물유형의 전국 확대

## 5. 데이터 & 외부 의존
- **외부 데이터 소스(개념)** — 실호출 경로가 아닌 **사전적재 대상**(헌법 §3-1):

  | 소스 | 용도 | 비고 |
  |---|---|---|
  | 국토부 실거래가(data.go.kr, 기관코드 1613000) | 매매/전월세 실거래 → 전세가율 계산 | **아파트·빌라 × 매매·전월세 = API 4종** · 강남구(11680) 최근 6개월 선적재 · 개발계정 키 즉시발급(대량은 운영계정 심의 1~2일) |
  | 건축물대장 | 건물 용도·노후도 | 강남구 한정 선적재 |
  | HUG 악성임대인 공개 명단 | 임대인 리스크 조회 | 차별화 핵심 · 유한 명단 통째 선적재 |
  | HUG 전세보증보험 가입 요건 | 체크리스트 콘텐츠 | 문서 기반(정적) |

- **인증 필요 여부**: MVP는 **개인정보 미취급 → OAuth 불필요**(헌법 §4 미적용).
  악성임대인 조회는 공개 명단 대조이며 사용자 개인정보를 카카오로 전달하지 않음.
- **개인정보 취급**: 없음. 입력(주소·보증금)은 조회용이며 저장/전송하지 않는다(무세션·stateless).

## 6. 비기능 요구 (제품 원칙 → NFR · 브리프 §4에서 승격)
1. **"안전하다" 판정 절대 금지.** 역할은 안전/위험 판정이 아니라 **위험 신호 탐지 + 확인 항목 안내**.
   - 금지: "이 매물은 안전합니다"
   - 허용: "전세가율 92%로 주의 구간입니다. 계약 전 등기부에서 근저당 여부를 확인하세요"
2. **모든 진단성 출력에 면책 문구 포함** ("참고용 1차 스크리닝, 법률 자문 아님").
3. **데이터 신뢰도를 출력에 포함**: 시세 산정 근거(비교 거래 건수 등)와 신뢰 수준 동반 반환.
   특히 빌라는 비교 실거래 부족 시 **"시세 신뢰도 낮음"을 명시**.
4. **tool 출력은 LLM 소비용 구조화 데이터** — 사람용 완성 문장이 아니라 LLM이 재구성하기 좋은 필드 구조.
5. **데이터 신선도 고지**: 사전적재 특성상 데이터는 주기적 스냅샷 기준 → 최신성 한계를 출력에 반영.
6. **model-agnostic**: 특정 LLM 의존 금지(예선 다양한 클라이언트, 본선 ChatGPT for Kakao).

## 8. 본선 확장 — 구현 완료 (예선 제출 이후)
> 예선 MVP(§3~§7) 이후 추가. **tool 개수는 3개 유지** — 신규 tool 없이 `diagnose_lease_risk`를 강화.
> 성격 구분: 8-1은 "폭"(위험을 보는 각도 추가), 8-2는 "깊이"(개별 매물 정밀도 상승).

### 8-1. 지역 위험 신호 (등기정보광장 IROS)
- **무엇**: 강남구 **임차권등기명령(집합건물) 월별 추세**를 diagnose 출력에 '지역 신호'로 추가
  (최근 3개월 vs 직전 3개월 → 증가/유지/감소).
- **왜**: 전세가율(개별)만 보던 한계 → **지역 차원 위험 축** 추가. 임차권등기명령 = 보증금 미반환의 직접 흔적.
- **성격**: 개별 정밀도가 아니라 지역 통계 → "강남구 전체 통계이며 개별 매물 상태 아님"을 출력에 명시.
- **데이터**: 등기정보광장 Open API(**개별 등기부 아님, 통계**). 사전적재 대상(§3-1). 미적재 시 신호 자동 생략.
- **§4 관련**: "등기부 실시간 연동"은 개별 조회가 유료·불가로 확인됨 → **통계 기반 지역 신호로 대체**.
- **§5 관련**: `HUG 악성임대인 명단`은 명단 극소수·실효 낮음으로 보류 → 지역위험 신호로 갈음.

### 8-2. 근저당 회수부담률 (사용자 입력 · human-in-the-loop)
- **무엇**: 사용자가 등기부에서 확인한 **선순위 채권최고액/보증금**을 diagnose에 선택 입력
  (`senior_debt`, `senior_deposit`).
- **계산**: **회수부담률 = (선순위 + 보증금) ÷ 시세**. 주어지면 이 기준으로 위험구간 판정(전세가율은 병기).
- **왜**: 개별 근저당 자동조회(유료 불가)를 **사람 입력으로 대체** → 개별 정밀도 실질 상승
  (같은 매물이 근저당 반영 시 판정 뒤집힘).
- **정책**: 시세 기준(A)으로 계산 + **낙찰가율(경매 낙찰가 70~80%) 주의를 출력에 고지**(B는 안내만).
- **개인정보**: 입력값은 즉시 계산에만 사용, 저장/전송 없음(무세션 유지 · §5·헌법 §4와 정합).
